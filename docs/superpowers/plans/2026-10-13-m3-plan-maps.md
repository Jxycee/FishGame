### T16.3 Behaviour

**`WorldSceneObjects.AddTo(scene, spotId)`.**
- `spotId` null or empty, or `scene` invalid: `ArgumentException`. A second call on a scene that already has a `World` root: `InvalidOperationException` ("one World per scene", C 11.3).
- Creates the root `World` (layer Default, identity transform, active) and moves it into `scene` (`SceneManager.MoveGameObjectToScene`, as `FishingSceneObjects`).
- Adds, in this order: `NetworkObject`, `WorldState`, `DevWorldDriver` (all on the one root: M3-D59; `WorldState.OnNetworkSpawn` finds its driver with `GetComponent`).
- Writes `spotId` through `new SerializedObject(worldState)`, `FindProperty("spotId")` (null -> `InvalidOperationException` naming the field: the T14 name is fixed, M3-D59), `stringValue = spotId`, `ApplyModifiedPropertiesWithoutUndo()`.
- NetworkObject settings: leave NGO defaults (no `AutoObjectParentSync` change, `SceneMigrationSynchronization` is set by NGO for in-scene objects). Do not set `DontDestroyWithOwner` or ownership flags: the host owns every in-scene object.
- Calls the private `RefreshHash(networkObject)` (reflection `OnValidate` + `SetDirty`, T16.4). Before the save this is a no-op for the hash (E-CCR-1); it is kept so that a builder that already saved the scene gets a hash too.

**`WorldSceneObjects.AddStandPoints(scene, xyzFacing)`.**
- Null list: `ArgumentNullException`; empty list: `ArgumentException` (a map without stand points can never pass reachability). A second call on the same scene: `InvalidOperationException`.
- Root `StandPoints` (layer Default, moved into `scene`), children `StandPoint_0..n-1` in list order: position `(x, y, z)` world, rotation `Euler(0, facingDeg, 0)`, layer Default, one `StandPoint` component with `Configure(facingDeg)`. **No collider, no renderer.**

**`WorldSceneObjects.FinalizeAfterSave(scene, scenePath)`** (E-CCR-1): code in T16.4.

**`ShoreGridBaker.BakeOpenScene(scene, target, minLandDepth)`:** code in T16.4. Rules:
- Mask Water | Shore | Ground, `QueryTriggerInteraction.Collide`; Structure and Default are not in the mask (under the dock is water; ladders, exits and reeds are invisible). Nearest hit Water -> water; Shore or Ground -> land; no hit -> void (neither water nor a distance seed). On an exact distance tie a non-Water hit wins (land), so the result never depends on hit order.
- Castable = water AND the cast gate (#26) at the cell centre with `minLandDepth`. Under the dock the cell is water (bake mask) but not castable (`CastProbe`'s mask includes Structure, so its first hit is the deck).
- Shore decimetres: `ShoreGridMath.ShoreDecimetres(water, land, 120, 120, 1)` (half-cell offset and caps: section B T7).
- Stand points: every `StandPoint` in `scene` (all roots, `GetComponentsInChildren<StandPoint>(true)`), in hierarchy order. None -> `InvalidOperationException` ("no StandPoint in <scene>"). Reachable bits: `ShoreGridMath.ReachableBits(..., castableBits, standXZ, EcologyConstants.ReachMinM, EcologyConstants.ReachMaxM)` (ring [4.9, 16.4] m, any facing, M3-D6).
- Writes `target.WriteBake(120, 120, 1f, -60f, -60f, shoreDm, castableBits, reachableBits, standPointPositions, scene.name)` (T9 2.2 signature; `id` untouched; GUID kept), then `EditorUtility.SetDirty(target)` and `AssetDatabase.SaveAssets()`.
- Logs one info line: `FG BAKE <scene> water=<n> land=<n> void=<n> castable=<n> reachable=<n> stands=<n> subAreas=<id>:<count>,<id>:<count>,...`. The sub-area counts come from `ShoreGridMath.CountReachablePerSubArea(target.ToCore(), zone)`, where the zone is the scene's spot zone (`ContentRegistry.TryGetSpotByScene(scene.name)` -> `Zone.ToCore(registry)`). When the spot is not registered yet (the harbour before T17's `BuildOrder` edit takes effect, which cannot happen inside a T17 build, see T17.4), print `subAreas=n/a`. Never a warning.
- Determinism: no `UnityEngine.Random`, no time, no hash containers; two bakes of the same scene give identical arrays, so the asset file is byte-identical across builds.

**`ShoreGridBaker.BakeAllMenu()`** (E-CCR-5): `EditorSceneManager.SaveCurrentModifiedScenesIfUserWantsTo()` (cancelled -> return); remember `EditorSceneManager.GetSceneManagerSetup()`; load the registry; for each registered spot (`registry.Spots`, so the harbour only from T17): open `ScenesFolder/<sceneName>.unity` with `OpenSceneMode.Single`, resolve its grid (`spot.Zone.ShoreGrid`; null -> log an error line and continue), read `minLandDepth` from `registry.FishingTuning.MinLandDepth`, `BakeOpenScene`; finally `RestoreSceneManagerSetup` (in `finally`). ### T16.4 Code (the bake loop and the hash step; write exactly, adapt only names that the merged code spells differently)

```csharp
// Editor/Builders/Ecology/ShoreGridBaker.cs - spec 12.5 bake, rulings M3-D6/D7/D8. Authority: none (editor; writes the grid asset only).
// One loaded scene with a WaterVolume at a time: two maps put a 120 m water box at the origin of the same physics scene (E-CCR-5).
public static void BakeOpenScene(Scene scene, ShoreGridDef target, float minLandDepth)
{
    if (!scene.IsValid() || !scene.isLoaded) throw new ArgumentException("scene is not loaded", nameof(scene));
    if (target == null) throw new ArgumentNullException(nameof(target));
    if (!(minLandDepth > 0f) || float.IsInfinity(minLandDepth)) throw new ArgumentOutOfRangeException(nameof(minLandDepth));
    RequireNoOtherWaterScene(scene);                  // throws InvalidOperationException naming the other scene
    Physics.SyncTransforms();

    const int w = GridWidth, h = GridHeight;
    int n = w * h;
    var water = new bool[n];
    var land = new bool[n];
    var castable = new bool[n];
    int mask = Layers.Mask(Layers.Water) | Layers.Mask(Layers.Shore) | Layers.Mask(Layers.Ground);
    var hits = new RaycastHit[64];
    int voids = 0;

    for (int cz = 0; cz < h; cz++)
    {
        float z = GridOriginZ + (cz + 0.5f) * GridCellSizeM;
        for (int cx = 0; cx < w; cx++)
        {
            float x = GridOriginX + (cx + 0.5f) * GridCellSizeM;
            int i = cz * w + cx;
            int count = Physics.RaycastNonAlloc(new Ray(new Vector3(x, RayTopY, z), Vector3.down), hits, RayLength, mask,
                                                QueryTriggerInteraction.Collide);
            if (count >= hits.Length) throw new InvalidOperationException("bake ray buffer full at cell " + cx + "," + cz);
            int best = -1;
            for (int k = 0; k < count; k++)
            {
                if (best < 0 || hits[k].distance < hits[best].distance) { best = k; continue; }
                // exact tie: a non-Water hit wins (land), so the result never depends on the unsorted hit order
                if (hits[k].distance == hits[best].distance && hits[best].collider.gameObject.layer == Layers.Water
                    && hits[k].collider.gameObject.layer != Layers.Water) best = k;
            }
            if (best < 0) { voids++; continue; }                                   // void: no water, no distance seed (M3-D7)
            if (hits[best].collider.gameObject.layer == Layers.Water)
            {
                water[i] = true;
                // C 2.8 #26: the cast gate itself (owner marker and host), at the cell centre.
                castable[i] = CastMath.ProbeReason(CastProbe.Probe(x, z), minLandDepth) == CastRejectReason.None;
            }
            else
            {
                land[i] = true;                                                     // Shore or Ground above the water
            }
        }
    }

    ushort[] shoreDm = ShoreGridMath.ShoreDecimetres(water, land, w, h, GridCellSizeM);
    byte[] castableBits = ShoreGridMath.PackBits(castable);
    StandPoint[] stands = CollectStandPoints(scene);   // hierarchy order; none -> InvalidOperationException
    var standXZ = new List<float>(stands.Length * 2);
    var standPositions = new Vector3[stands.Length];
    for (int s = 0; s < stands.Length; s++)
    {
        Vector3 p = stands[s].transform.position;
        standPositions[s] = p;
        standXZ.Add(p.x);
        standXZ.Add(p.z);
    }
    byte[] reachableBits = ShoreGridMath.ReachableBits(w, h, GridCellSizeM, GridOriginX, GridOriginZ, castableBits, standXZ,
                                                       EcologyConstants.ReachMinM, EcologyConstants.ReachMaxM);

    target.WriteBake(w, h, GridCellSizeM, GridOriginX, GridOriginZ, shoreDm, castableBits, reachableBits, standPositions, scene.name);
    EditorUtility.SetDirty(target);
    AssetDatabase.SaveAssets();
    LogBake(scene, target, water, land, voids, castable, reachableBits, stands.Length);   // the FG BAKE line (T16.3)
}
```

```csharp
// Editor/Builders/Ecology/WorldSceneObjects.cs - E-CCR-1. NGO 2.13.3 computes GlobalObjectIdHash in the internal
// NetworkObject.OnValidate from GlobalObjectId.GetGlobalObjectIdSlow, which is null (identifierType 0) until the scene is saved.
private static readonly MethodInfo s_onValidate =
    typeof(NetworkObject).GetMethod("OnValidate", BindingFlags.Instance | BindingFlags.Public | BindingFlags.NonPublic);

internal static void FinalizeAfterSave(Scene scene, string scenePath)
{
    if (string.IsNullOrEmpty(scene.path)) throw new InvalidOperationException("save the scene before FinalizeAfterSave");
    NetworkObject networkObject = FindWorldRoot(scene).GetComponent<NetworkObject>();   // InvalidOperationException if no World
    RefreshHash(networkObject);
    if (HashOf(networkObject) == 0u)
        throw new InvalidOperationException("World GlobalObjectIdHash is still 0 after OnValidate in " + scenePath);
    BuilderUtil.SaveScene(scene, scenePath);           // second save writes the hash; file ids are unchanged within one build
}

private static void RefreshHash(NetworkObject networkObject)
{
    if (s_onValidate == null) throw new MissingMethodException("NetworkObject.OnValidate not found (expected internal in NGO 2.13.3)");
    s_onValidate.Invoke(networkObject, null);
    EditorUtility.SetDirty(networkObject);             // C2 #4: OnValidate dirties only on a change in memory
    EditorSceneManager.MarkSceneDirty(networkObject.gameObject.scene);
}

private static uint HashOf(NetworkObject networkObject)   // the serialized field, as the validator reads it
{
    using var so = new SerializedObject(networkObject);
    SerializedProperty p = so.FindProperty("GlobalObjectIdHash");
    if (p == null) throw new InvalidOperationException("NetworkObject.GlobalObjectIdHash property not found");
    return p.uintValue;
}
```

### T17.3 Art (R74 style guide; the T4-adopted code)
- **No faceting.** Every new mesh except the water grid uses `SmoothMeshBuilder` (as adopted by T4) or a smooth height field. `MeshBuilder` (flat) only for `Harbour_Water`.
- **Material.** Every environment renderer uses `M_Toon_Base` (palette mode, env `ToonLook`, the env detail array). No new material, no new texture, no new texture-array layer: the harbour uses the existing layers (`EnvTextureLayers` Sand, Grass, Wood, Bark, Rock, Foliage, Cloth). So no LFS growth.
- **uv1 on every vertex** = (palette slot, texture layer, mapping, 0); slots are `LakeDockLayout.Slot*` (spec 10.2 order). Season swaps then tint every prop through the palette (#27).
- **Vertex colour** = half-scale grey `0.5 x ao` (BF-7, `_JitterEncoded` 1), so `RenderValidators.ToonMeshesHaveVertexColours` passes for the new scene (it walks every `BuildOrder` scene).
- **Recipes** (style guide 2.4/2.5):
  - Seabed: height field, Sand slot and layer, uv0 = world xz, ao 1 near the coast to 0.8 at 9 m depth (the water's depth fade does the rest). One mesh serves the `MeshFilter` and the `MeshCollider` (a new map has no M1 collider to keep; the guide's visual-twin rule protects existing colliders only). Normals from the slope `dY/dz`, central difference over 1 m, so the coast and the 9 m kink shade softly.
  - Beach and plateau: the same height field; Sand slot and layer below y 0.6, Grass above, one slot per row band (a band boundary duplicates its row, as the lake's `FillRadialSmooth`), macro breakup comes from the material.
  - Pier: rounded-box planks across the deck (0.26 m wide, 0.04 m gap, bevel 0.02, wood layer 3, grain along each plank, ao 0.45 toward the bottom), one draw per plank from `harbour_pier.planks` for the slot (Wood or Dock) and one for a yaw of +-0.8 deg (the lake's `AddPlank` rule; tops exactly at 1.5); two WoodDark stringers under the deck; T-head planks run along z; ramp planks along the ramp. Posts are lathes (radius 0.09, 12 sides, grain up with `swapUv`, ao darker toward the bed and under the deck). Ladders: two rails and rungs every 0.3 m inside each ladder's rail box, WoodDark.
  - Breakwater: `Radial` boulders (the lake rock recipe: two noise octaves plus a rounded-box bias, flattened base, Rock slot, Rock layer, triplanar, ao 0.62 at the bottom to 1.0 on top), radius 0.8-1.3 m, two rows along the sides at 1.6 m spacing (draws from `harbour_pier.stones`: radius, yaw, a +-0.2 m jitter) and a rounded-box path on top (Rock slot, Sand layer, top exactly 1.5). Visual only; the collider is the box.
  - Rocks: `Harbour_Rock`, the lake rock recipe with the harbour seed, inside the unit sphere (so the sphere collider bounds it).
  - Props: bollards (lathe, Accent slot), crates (rounded boxes, Wood), barrels (lathe with two hoop bands, WoodDark and Rock), lamp posts (lathe pole WoodDark, `Radial` lamp head Accent), hut (rounded-box walls Wood, a two-plane rounded roof Roof, a Dock door). Each prop has one box collider on Structure under the `Props` root; the visuals are one combined mesh.
- **Meshes and limits.** `Harbour_Water`, `Harbour_Seabed`, `Harbour_Beach`, `Harbour_PierDeck` (main-deck planks and stringers), `Harbour_PierHead` (T-head and ramp planks), `Harbour_PierPosts`, `Harbour_Ladders`, `Harbour_Breakwater`, `Harbour_Props`, `Harbour_Rock`, under `AssetPaths.MeshesFolder`, paths as `HarbourPierLayout` constants. Every mesh asserts at most `LakeDockLayout.MaxCombinedTriangles` (21,000) triangles in the builder (`InvalidOperationException` naming the mesh); if one is over, split it into `_A`/`_B` and report. The water and the height fields use 16-bit indices (vertex counts under 65,535).
- **Saving.** `HarbourPierMeshes` copies the lake's save-in-place helper privately (`EditorUtility.CopySerialized` into the existing asset; create only when missing). Never delete and recreate a mesh asset. Fixed seeds, fixed draw order, no `UnityEngine.Random`: two builds leave every `Harbour_*.asset` byte-identical.
- **Value range and readability** (guide 2.3, spec 10.2): no gameplay meaning in texture alone; the deck edge and the ladders must read against the water (WoodDark against the sea's blue-green); the bell stays the M2 bell.

## Risks (section E)

1. **The first in-scene NetworkObject (C 15 #2).** The hash needs a saved scene (E-CCR-1) and changes with every build, so host and clients must run the same scene file, and a Spot scene is always committed whole. The MPPM check (T16.7) must pass before T15; the M3-D18 fallback is named and costs one fix task (prefab, network prefab list, anchor, a `WorldState` spot lookup).
2. **`World` now spawns in every lake PlayMode test.** Any warning from `DevWorldDriver`/`WorldState` (an unresolved zone, an unbaked grid, a planner without cells) fails PlayMode. T16 is the first run of T14's code in a scene: expect integration fixes there, not in T15.
3. **Reeds reachability rests on Q1 (`minLandDepth` 0.5, M3-D52).** The castable reeds ring is only about 1.4 m wide (shore distance 3.3-4.8 m). If `FG BAKE` shows `reeds` below 25, the lever is the Q1 alternative (a near-shore shelf in the lake bed), a user decision, not a code fix.
4. **Registry cache vs. bake.** `ContentRegistry` caches its ecology database; anything that reads `registry.Ecology` in the same BuildAll after the bake sees the old grid. `MapChecks` and the tests build zones fresh (`ToCore`). Runtime is unaffected (a fresh process loads the baked asset).
5. **Harbour performance.** The 240 m water grid has about 51,000 triangles (the lake's about 18,000), and the R73 water shader is the most expensive pass. The user's spec 10.7 perf check (T25) covers it; the fallback is a 120 m grid plus a coarser skirt ring, at the cost of a visible seam risk.
6. **Look-dev drift.** T17 is written against the look-dev branch code; the T4 adoption has landed (d660ee9) but may have renamed or extended `SmoothMeshBuilder`. T17's pre-flight re-reads the merged code and follows it; the recipes here are behaviour, not code.
7. **Spot index shift.** Adding the harbour makes it spot 0 and the lake spot 1 (ordinal sort). A hidden "lake is 0" assumption would break silently; T17.5 greps for it.
8. **Two Spot scenes in one physics scene.** Opening both maps additively in the editor stacks two water boxes at the origin; the bake refuses (E-CCR-5), and the validators open one scene at a time.
