# REPO + PEAK reverse-engineering notes (mechanics/numbers only; Photon PUN -> translate to NGO)
Source: ILSpy of Assembly-CSharp.dll copies in scratchpad/re/{repo,peak}/src. Hard-coded constants only; AnimationCurves / ScriptableObject presets / prefab values (audio min/max distance, per-valuable value ranges, spawn-count curves) are asset data NOT in the DLL -> marked "asset".
Currency unit in REPO: "dollars" internally, display/currency = dollars/1000 (K).

## 1. REPO quota / level economy
- Goal formula (`RoundDirector.StartRound`, host only): `haulGoal = (int)( haulGoalMax * 0.7f * curve(diff) )`.
  - `haulGoalMax` = SUM of `dollarValueCurrent` of every valuable the level actually spawned (`ValuableObject.DollarValueSet` does `RoundDirector.haulGoalMax += value`). So the quota is a fraction of what is *on the map*, never an absolute number -> quota is always reachable if you find ~70%*curve of the loot.
  - `curve` = `haulGoalCurve1.Evaluate(RunGetDifficultyMultiplier1())` while levelsCompleted<=9, else `haulGoalCurve2.Evaluate(RunGetDifficultyMultiplier2())` (curves = asset, unknown shape).
  - `SemiFunc.RunGetDifficultyMultiplier1 = clamp01(levelsCompleted/9)`; `Multiplier2 = clamp01((levelsCompleted-9)/10)`; `Multiplier3 = clamp01((levelsCompleted-19)/10)`. => 3 difficulty bands: levels 0-9, 10-19, 20-29 (then clamped flat).
  - Level loot budget also curve-driven: `ValuableDirector.totalMaxValueCurve1/2` + per-size max-amount curves (tiny/small/medium/big/wide/tall/veryTall) evaluated by the same multipliers; hard cap `totalMaxAmount = 50` objects (Arena halves it).
- Multiple extraction points per level: each point's goal = `haulGoal / extractionPoints` (`ExtractionPoint` button press). Extraction takes `haulGoal + surplus`; currency += `ceil(extractionHaul/1000)` (`ExtractionPoint` ~l.2017-2021). Surplus above goal is spawned back as a single "tax return" valuable (value override = surplus; Small <=5000, Medium <=10000, Big >10000 prefab) so overshoot is never lost.
- Only valuables standing in an extraction volume count (`RoomVolume.Extraction`) -> host polls every 0.5s, add/remove from `dollarHaulList`; `HaulCheck()` sums `dollarValueCurrent` (damaged value), `currentHaulMax` sums original.
- Levels: `RunManager.levelsCompleted++` on success; `moonLevel = (levelsCompleted+1)/5` (cosmetic tier every 5 levels). After each completed level -> random Shop scene -> next level.
- FAIL: there is NO quota-fail timer. You fail only if ALL players are dead/disabled (`RunManager.Update` allPlayersDead check, host) -> `ChangeLevel(false, true)` -> Arena (PvP last-man-standing, random of `levelArena`; solo -> arena[0]) -> after arena ends `ResetProgress()`, `gameOver=true`, back to lobby. Lives var `runLives = 3` exists but death flow above is what ships. (`StatsManager` saves run: `saveLevel` 0 none/1 shop/2 lobby = mid-run save for rejoin.)
- Shop pricing (`ShopManager`, `ItemAttributes.GetValue`): `price(K) = ceil( max(rand(itemValueMin,itemValueMax)*4f, 1000)/1000 )` (`itemValueMultiplier=4`). Roll is per item instance, host only, RPC'd to others.
  - Upgrades: `UpgradeValueGet`: `v -= v*0.1*(min(6,players)-1)` (10% discount per extra player, cap 5 extra=-50%); `v += v*0.5*timesAlreadyBought(item)` (+50% each purchase, cumulative linear); `ceil`.
  - Health pack: same player discount; `+= v*0.05*min(levelsCompleted,15)`.
  - Power crystal: `+= v*0.2*min(levelsCompleted,15)` (no player discount).
  - Stock: `maxAmountInShop - alreadyPurchased`, skip if `value.maxPurchase` cap hit or `minPlayerCount` > players; item not affordable (`price > totalCurrency`) is kept only 25% of the time (`Random.Range(0,100) < 25`) -> shop mostly shows what you can afford plus an occasional dream item. Consumables per shop: `Random.Range(4,6)` (4-5).
  - Shop purchase = same physical extraction mechanic: you *carry items into the shop's extraction pad*; goal there = `StatGetRunCurrency()*1000`, haul = `ShopGetTotalCost()*1000`; button only valid when cost <= currency (`ExtractionPoint.isShop`).

## 2. REPO valuables
- Value roll (`ValuableObject.DollarValueSetLogic`, host, RPC'd): `v = round(rand(preset.valueMin, preset.valueMax)); v = round(v/100)*100`. Presets are ScriptableObjects (`Value`: default min100/max200; asset). `dollarValueOverride` bypasses (tax return, debug).
- Per-object `Durability` preset: `fragility` (0-100, scales incoming impact) and `durability` (0-100, scales loss size). `PhysAttribute` preset gives mass.
- Impact detection (`PhysGrabObjectImpactDetector.FixedUpdate`, host only): per physics tick
  - `dv = |prevSpeed - speed|` where speed = `rb.velocity/fixedDeltaTime`; `dw = |prevAngSpeed - angSpeed| * 0.4 * mass`; direction change terms `angle*0.2` and `angAngle*0.02*mass`. An impact counts if any term >1 and the relevant speed >1.
  - `breakForce += dv*2 * max(mass,1)`; `breakForce *= 8`; `impactForce = breakForce/8 * impactFragilityMultiplier`; `breakForce = breakForce * (fragility/100) * fragilityMultiplier`.
  - Sound/FX tiers on `impactForce`: >20 Light, >80 Medium, >150 Heavy (0.5s cooldown shared).
  - BREAK tiers on `breakForce > L * max(mass,1)` with L = 300 (Light=1), 400 (Medium=2), 500 (Heavy=3); highest wins; cooldowns 0.3/0.4/0.6s; no break while `inCart` (breakForce zeroed in cart, impactForce x0.3) or during `indestructibleSpawnTimer`.
  - Value lost = `round(original * base * (1 + 9*(100-durability)/100))` +-10% random, with base = 0.01 (Light), 0.05 (Medium), 0.10 (Heavy). I.e. a 0-durability object loses 10x as much per hit (Heavy: 100% of original; durability 100: 10%). Heavy clamps lost to [1, current]. Result `dollarValueCurrent -= lost` (host RPC `BreakRPC` to all).
  - Destroyed (`DestroyObject`) when `current < 0.15 * original`.
  - Thrown-into-wall extra: separate path (~l.1520-1560) applies `BreakHeavy` with a minimum loss = original * {Medium 1/7, Big/Wide/Tall/VeryTall 0.1 (+-0.05)} (volume-size based) -> big things can't be thrown for free.
  - Break also calls `EnemyInvestigate(10)` -> noise lure radius 10 (BreakHeavy/Medium/Light all "flag").
- Physics clamp: host clamps rb velocity 40 m/s, angular 30 rad/s (`PhysGrabObject.FixedUpdate`).
- Healing exists (`ImpactDetector` heal path l.806-830: current += heal up to original) -> repair items.
- Extraction/selling flow: see 1. Valuables auto-despawn ("suck up") into the tube; surplus returns as new valuable.

## 3. REPO physics grab (`PhysGrabber`, `PhysGrabObject`)
- Defaults (`PhysGrabber`): `grabRange 4`, `grabReleaseDistance 8`, hold distance clamp `min 1 .. max 2.5` m from camera (scroll adjusts), `springConstant 0.9`, `dampingConstant 0.5`, `forceConstant 4`, `forceMax 4`, `physGrabPointPullerDampen 80`. Upgrades: strength +0.2/level (`grabStrength` base 1), throw +0.3/level (`throwStrength` base 0), range +1 m/level.
- Force law (`PhysGrabObject.PhysicsGrabbingManipulation`, FixedUpdate, HOST ONLY: `if (Multiplayer && !isMaster) return`): per grabber
  - `d = clamp(pullerPos - grabPoint, forceMax)*10` -> `d = clamp(d, forceMax)`;
  - `a = clamp(d*spring - pointVelocity*damping, forceMax) * 2 / mass`;
  - `strength' = lerp(s, s/(1+min(s,30)), min((s-1)/k, 0.9))` with k = 7 (mass<2), 20 (2-8), 20 (>=8) -> diminishing returns on strength upgrades;
  - `F = a * strength' * forceConstant(4)`; ramps with distance `min(dist*10,1)`; smoothed `Lerp(prevForce, F, 0.8)`; `rb.AddForceAtPosition(F, grabPoint, ForceMode.Acceleration)`. Acceleration mode => heavier = slower automatically through `/mass`. Standing on the object zeroes the upward component (can't lift yourself).
  - Because force is clamped at `forceMax`, ANY object accelerates at <= ~4*2*strength*4/mass m/s^2: mass is the only difficulty knob.
- Multi-player carry: `playerGrabbing` list; each grabber adds its own force at its own grab point -> forces just sum (so two grabbers = 2x pull, plus torque differences = comedic swinging). Guns/melee divide force by grabber count (`isMelee||isGun`). Hinged objects (doors) x2. Carts x0.25 rotation.
- Rotation: hold Rotate key; mouse delta scaled by `lerp(0.1,1,mass*0.05)`, x15*strength, clamp 70; angular drag override `40*clamp(1/mass,0,0.5)`; max 45 deg step per update vs. current rotation.
- Throw (`PhysGrabObject.Throw` on release): `impulse = clamp(pullerPos - grabPoint, forceMax) * max(mass*1.5,1) * (0.5 + throwStrength)` -> release while the pull-point is leading = throw; no separate throw button. Mass-compensated (impulse ∝ mass).
- "Overcharge": grabbing very heavy/strained objects fills `physGrabBeamOverCharge` (0..1, sent as byte *200); at 1 launches the player (`OverChargeLaunchPlayer`) -> built-in comedic fail state.
- Authority: ALL non-player physics objects are simulated on the host (clients' `PhysGrabObject.isMaster=false` -> rb not driven; they receive `rbVelocity`, `rbAngularVelocity`, `isSliding`, `isKinematic` in `OnPhotonSerializeView` and extrapolate via `PhotonTransformView`). Ownership is pinned to `MasterClient` (`photonView.TransferOwnership(MasterClient)` in Start/spawn), NEVER moved to the grabber. Client sends *input only*: `PhysGrabber.OnPhotonSerializeView` streams `physGrabPointPullerPosition` (where the hand wants to be), `physGrabPointPlane`, `mouseTurningVelocity`, `isRotating`, colour state, overcharge byte; host reads puller point and applies force. Grab start/end are RPCs to MasterClient (`GrabStartedRPC`/`GrabEndedRPC`, with `OwnerOnlyRPC` check that the sender owns the PhysGrabber). `GrabLink` RPC carries local hit point + camera-relative forward/up so host can orient.
- Cheap-client trick: `clientNonKinematic = true` for Tiny/Small valuables (`ValuableObject.Start`: volumeType <= Small) so small things are locally non-kinematic (less visual lag), host still authoritative. Network rates: `PhotonNetwork.SerializationRate = SendRate = 25` (NetworkManager).
- Impact events happen host-side and are broadcast (`BreakRPC` etc.), clients never compute value loss.

## 4. REPO downed / death / revive / spectate
- No downed state. HP 100 (+upgrade) -> `PlayerAvatar.PlayerDeathRPC` -> death. `Hurt` has a "saving grace": if damage<=25 and health in (5,20] you survive with 1-4 hp (`Random.Range(1,5)`).
- On death: player body hidden, a physics DEATH HEAD (`PlayerDeathHead`, a normal grabbable `PhysGrabObject`) is spawned at the death spot; `deadTime=0.5s`; local death penalty `ProgressionManager.penaltyDeath += 0.05` (cap 0.5, XP-ish). `isDisabled=true`. Held object released.
- Spectate (`SpectateCamera`): states Death -> Normal (free-orbit follow, Jump/SpectateNext/Prev cycle players; spectator voice becomes non-spatial for the viewed player: `voiceChat.SpatialDisable`) -> Head (possess your own head). Head possession uses an energy battery: drain `dt/25` per sec base (so 25 s of control), each `upgradeDeathHeadBattery` level adds `5 * 0.95^n` s; charge-jump drains 2x; while spectating normally recharges `dt/100` (100 s for full) and needs >=0.25 (=25 s) to enter. Interact toggles out. So dead players keep a *limited, comedic* agency (roll/hop the head to bring it to friends).
- Revive: (a) carry head into the TRUCK (start room): `inTruckReviveTimer = 2f` of continuous presence -> `PlayerAvatar.Revive(true)` + `TruckHealer.Heal`; (b) consumable `ItemReviveItem` (reviveTime 5 s, failSafe 15 s) -> `Revive()` + `HealOther(49)`. Revive teleports avatar to head position, 1 s invincibility, voice mixer restored, enemies ignore its voice for 1 s (`OverrideDisableEnemyInvestigate`). Both host-RPC'd (`MasterOnlyRPC`).
- If everyone is dead -> level fails (see 1). Dead player's haul contribution is unaffected; `deadPlayers` counted on RoundDirector.

## 5. REPO proximity voice
- Photon Voice 2; each remote player has an `AudioSource` (`spatialBlend` 1 = 3D; set 0 for self/lobby/spectator, `PlayerVoiceChat`). Min/max distance + rolloff curve are on the prefab (asset, not in DLL).
- Occlusion (`AudioLowPassLogic`, runs on every spatial sound incl. voice): when blocked (LayerMask Default/PhysGrabObject/Hinge raycast) -> lowpass cutoff slides from 22000 Hz to 1000 Hz (down at 10x range/s, back up at 1x), `maxDistance *= 0.8` (custom falloff), `volume *= 0.5`, spatialBlend lerps toward 1. Crouching/crawling uses a different TTS voice and `lowPassLogicTTS.Volume = 0.8`.
- MONSTER-ATTRACTING VOICE (yes): host-only per player (`PlayerVoiceChat.Update`, `IsMasterClient`): `clipLoudness` (mean |sample|, x mic-volume setting/100) thresholds: standing >0.025; crouching >0.05; crawling needs >0.05 for >10 consecutive checks; dead-head spectated >0.05. If hit and `investigateTimer<=0` -> `EnemyDirector.SetInvestigate(visionPos, radius=5)`; timer 1 s. `SetInvestigate` wakes every enemy whose `distance / enemy.StateInvestigate.rangeMultiplier < radius` (per-enemy range multiplier = some enemies hear far better; radius >=15 also reduces spawn cooldown of unspawned enemies by 5 s). Revived players have a 1 s grace. Physics noises use the same system (`EnemyInvestigate(10)` on break, 20 at extraction button press outside start room).
- `isTalking` flag (loudness>0.005, 0.5 s hold) drives mouth animation (`PlayerAvatarTalkAnimation`) and `OverrideAddToClipLoudnessAnimationValue` lets effects fake loudness.

## 6. PEAK stamina / climb / co-op help
- Stamina is a 0..1 float, owner-authoritative (`CharacterData.currentStamina`, synced in `CharacterSyncData`). `extraStamina` = separate 0..1 "bonus" pool consumed only when regular is 0 (food/morale), also hard-capped by petrify.
- MAX stamina cap = `1 - afflictions.statusSum` (`Character.GetMaxStamina`): every affliction (Injury, Hunger, Cold, Poison, Curse, Drowsy, Weight, Hot, Thorns, Spores, Web, Crab, Arrow, Petrify, FlyTrap = 15 types) is a 0..1 slice of ONE shared bar; `statusSum > 0.99` => pass out (`shouldPassOut`). Slices are shown as coloured segments on the stamina bar (`StaminaBar`). Elegant: no HP, afflictions *eat the stamina ceiling*.
- Regen: `+0.2/s` (`FixedUpdate` `AddStamina(dt*0.2)`) only when `CanRegenStamina`: not using stamina for 1 s (2 s if stamina hit 0); must be grounded (`sinceGrounded<=0.2`, except while holding a climb handle or webbed/stuck). `staminaMod = max(clamp01(total*5), 0.2)` scales movement as you tire.
- Costs: sprint `sprintStaminaUsage 0.025/s`; climbing `maxStaminaUsage 0.2/s * clamp(input,0,1)`, floor `minStaminaUsage 0.02/s`; climb-jump flat `0.2`; reaching to next grip `0.15 * distance(>=0.1)`; kick `1.0` (whole bar); ground jump costs prefab-set; rope grab `staminaUsageGrab 5` (prefab). Out of stamina while climbing -> `outOfStaminaClimbingFor` ramps slide: `200 * clamp01((clamp(t,0,5)*0.15)^2)` px/s^2 -> you slide faster the longer you hang empty. All costs x `Ascents.climbStaminaMultiplier` (0.7 / 1 / 1.4 by difficulty).
- Injury source: FALL DAMAGE (`CharacterMovement.CheckFallDamage`): airtime beyond `fallDamageTime 1.5 s` (after ~0.125-0.375 s grace): `dmg = ((t-1.5)/(3-1.5))^1.5`, min 0.05, capped by vertical speed `((|vy|-10)/(20-10))^1.5` (so you can't die from a slow fall); >=0.025 applies as `Injury` status; >0.3 also ragdolls for `dmg*5` s. x `Ascents.fallDamageMultiplier` (0 / 0.5 / 1 / 2 by setting; 2 from ascent 1).
- Weight: each carried item `CarryWeight` int; `Weight status = 0.025 * sum` (so 10 weight = 25% of bar). Thorns/arrows add `0.025` each. CARRYING A FRIEND adds +8 weight (=0.2 of the carrier's bar). Backpack counted.
- Hunger passive `0.0005/s` (x ascent mult), cold night `0.005/s` (ascent>=5).
- Co-op help (all LOCAL-owner simulated, no host):
  1. REACH/pull-up (`CharacterGrabbing.Reach`): helper holds reach (no item, not climbing): every character within 4 m, in a 60 deg cone, that `TargetCanBeHelped` (stuck / struggling / climbing and at least 1 m *below* helper) gets, on THEIR OWN client, `DragTowards(helper reach point, 70)`, `LimitFalling()`, and web/flytrap statuses -1. Helper's `sinceGrabFriend` resets -> the climbing target pays only reduced reach stamina (`sinceGrabFriend>0.5` gating on the 0.15 cost). Also rag-doll grab: `GrabAttach` FixedJoint hand-to-bodypart (scoutmaster NPC only); a grabbed player breaks free with Jump.
  2. PAL JUMP / boost (`CharacterMovement.StandOnPlayer/CheckForPalJump`): friend CROUCHES, you land on them while NOT crouching; if they jump within 0.3 s of you standing on them (`sinceStandOnPlayer<0.3 && other.sinceJump<0.3`) you get `JumpRpc(isPalJump)`: jump x2 (`jumpMult=2`), free stamina, forward bias `lookDir*0.25`, 0.5 s cooldown. Pure emergent physics co-op, no special item.
  3. ROPE: `RopeShooter` (startAmmo 1, maxLength 30), `RopeSpool` (fuel 60, min segments 3.5), segment spacing 0.75 m, host-synced (`RopeSyncer`/`SyncData`); anyone climbs (`CharacterRopeHandling`, drag 0.85, `maxRopeAngle 90`).
  4. RESCUE HOOK item (`RescueHook`): range 30 (40 down), maxLength 40, `dragForce 100`, `liftForce 1000`, lifts up to 10 m, wall hook lasts 1 s / friend hook 2 s; pulls a friend (or self) to the point.
  5. CARRY (see 8). Kick (HelpingHand run setting off): `kickForce 10`, range 3, 45 deg, 0.6 s windup, 1 s ragdoll on victim, costs whole stamina bar, force scaled `1 + (staminaUsed-0.1)*2`.

Segments for progress: Beach, Tropics, Alpine, Caldera, TheKiln, Peak (+Void).
- DAILY LEVEL: `NextLevelService`: `levelIndex = floor( hoursSince(2025-06-14 17:00 UTC) / 24 )`, server-queried (`LoginResponse.LevelIndex`, with offline fallback computing the same), scene = `MapBaker.GetLevel(index % ScenePaths.Length)`. Everyone worldwide gets the same island for 24 h; a countdown to the next one is shown on the airport kiosk (`AirportCheckInKiosk`, `NextLevelUI`). Seed is a *day index*, not an RNG seed.
- Items/luggage are runtime-rolled by host `Spawner` (host only, `PhotonNetwork.IsMasterClient`): modes `SingleItem / SpawnPool (flags enum per biome: LuggageBeach/Jungle/Tundra/Caldera/Mesa/Roots/Cursed/Clown..., Campfire, RespawnCoffin) / HeightBasedSpawnPools (pool by altitude+biome) / Guidebook`; `baseSpawnChance`, weighted spawn-point lists, `playersInRoomRequirement`, `belowAscentRequirement`, `normalRunsOnly`. Spawn history is tracked so reconnecting clients rebuild identical items (`SpawnAndTrackFromItemHistory`).
- Difficulty = "Ascents" 0..9 (-1 = easy): knobs (`Ascents`): fall dmg x2 (>=1), hunger x1.6 (>=2) (x0.7 on -1), item weight +1 (>=3), no flare at peak (>=4), cold nights (>=5), climb stamina x1.4 (>=6), start curse 0.1 + revival curse 0.15 (>=7, else 0.05), requires "Nadir" (>=8). Custom runs expose ~60 `RunSettings` toggles (fog, hunger rate, fall damage, item weight, climb stamina, revival allowed, hazard on/off per type, MiniRun, GrappleMode stamina x4, ChaosItems, TimeScale, HelpingHand, Firearms...).
- Pacing: day length `dayLengthInMinutes 10`, dayStart 5h, dayEnd 21h, start 9h (`DayNightManager`); campfire burns 180 s, cook time 5 s (`Campfire`); optional LavaRising (initialWait 1 s, travelTime 60 s debug; real values prefab) = time pressure; checkpoints are campfires/segments (`Campfire_Set_Segment`, `lastRevivedSegment`).

## 8. PEAK downed / revive / carry
- States: conscious -> `passedOut` (status sum > 0.99, 5 s fade `passOutValue += dt/5`) -> `fullyPassedOut` (= downed, on the ground, ragdoll control 0) -> `dead` (body warped to `DeathPos = (0,5000,-5000)`) or zombie.
- Death timer (`Character.UpdateVariables`): while `fullyPassedOut`: no carrier => `deathTimer += dt/60` (60 s to bleed out); if nobody else conscious and no meaningful temp statuses => `dt/10` (10 s); holding Interact (give up) => `dt*0.33` (3 s). CARRIED => timer frozen. Auto un-pass-out if `statusSum<1` for >3 s (someone fed/healed you).
- Carry (`CharacterCarrying`): interact on a downed friend (`CharacterInteractible`): carrier unequips item and drops backpack contents (backpack item spawned at the torso by host); `RPCA_StartCarry` flags `isCarried`, carried player's collisions turn OFF, carried ragdoll control = 1 (`GetTargetRagdollControll` returns 1 if carrier). Carry force runs on the CARRIED player's own client each FixedUpdate: `AddForce( clamp(carrier.carryPosRef + carrier.avgVel*0.06 - center, 1) * 500 )` + extra drag 0.5 -> a soft spring-follow (owner-simulated; no ownership handoff). Interact again to drop; auto-drop if carried recovers/dies. +8 weight to carrier. Statuses web/flytrap cleared on pickup.
- Revival (`Character.ReviveCharacter/RPCA_ReviveAtPosition`): `ScoutEffigy` (constructable item; only usable if somebody is dead/down; revives a RANDOM dead teammate at preview point +1 m), `RespawnChest`/coffin at campfires (`Ascents.canReviveDead`), warps player, drops all items incl. backpack, clears all statuses, petrify -0.75, then applies "post-revive" statuses: `Curse = Ascents.revivalCurse (0.05 / 0.15)` + `Hunger 0.3` (so revived players have ~35% less stamina bar; revival has a persistent cost). Revival teleports + marks biome skipped for achievements.
- Dead players spectate (`spectateZoom` synced); `ReconnectData` stores statuses/thorns/position/deathTimer for rejoining players (host re-applies).

## 9. PEAK voice + comedic ragdoll
- Voice: Photon Voice (`Recorder` per `CharacterVoiceHandler`), push-to-talk/mic settings, `audioLevel` default 0.5, `muffleAttenuation 0.85` (+lowpass). Spatial; `VoiceObscuranceFilter` per voice: linecast speaker->listener head blocked => lowpass cutoff lerp to 1500 Hz else 7500 Hz; beyond 60 m (`sqrMag>3600`) adds echo (wet 0.35, delay 500 ms, decay 0.3) so far voices sound like distant cave shouts; reverb mix from `LightVolume` (shade/indoor alpha, max 0.9). Muffled (cutoff 285 Hz, resonance 1.1) when the speaker OR listener `isStruggling`/dead; `stolenVoiceCutoff 1000 Hz` + `IsStolen` -> voice transform can be overridden by an item/creature (voice comes out of another object, ie. a comic hazard hook).
- No mechanic ties talking volume to monsters in PEAK (only REPO).
- Active-ragdoll core (`CharacterRagdoll`, `Bodypart`, `CharacterMovement`): every body part has a Rigidbody + ConfigurableJoint (`rig.maxAngularVelocity=50`). A hidden animated rig is evaluated each FixedUpdate; each `Bodypart.Animate(force, torque)` drives (a) `joint.SetTargetRotationLocal(animLocalRot)`, (b) `AddTorque(cross-product angle error * torque, Acceleration)`, (c) position spring `AddForce((animTargetPos - com)*force, Acceleration)` with equal/opposite reaction (-0.5 * mass*force) split onto joint parent and hip. Defaults: `animationForce 100`, `animationTorque 10`, `movementForce 10`, `drag 0.85`, `maxGravity -20`, `jumpGravity 10`, `standSmooth 0.2` + `standForce` pushes head+torso up toward target head height.
- THE single comedy knob: `currentRagdollControll` 0..1 multiplies `animationForce`, `animationTorque`, movement force, gravity-on/off (`ToggleUseGravity(control<0.9)`) and physic material (control<0.9 => Grippy else Slippery). Target (`CharacterData.GetTargetRagdollControll`): 1 if carried; 0 if `fallSeconds>0`, passed out, dead; else `min(1, 1-passOutValue, ragdollControlClamp)`. Dynamics: control DROPS instantly to target, RECOVERS at +1/s above 0.5 and +0.5/s below 0.5 (so a hard fall = ~2 s floppy then rises) (`Character.UpdateVariablesFixed`). `Fall(seconds)` (RPC to all) sets `fallSeconds`; counts down 1x grounded, 0.2x airborne. Triggers: fall damage >0.3 (`a*5` s), out of stamina while moving, kick, explosions, `Fall(7)` etc.
- Remote players: owner simulates its own full ragdoll; stream is tiny (`CharacterSyncData`: hip position, look, move input, sprint/climb/grounded flags, stamina, rope %, climbPos, groundNormal, avg velocity, petrify); remote copies re-run the same animation-driven ragdoll from those inputs and are position-corrected -> floppiness is visible and slightly different per client but never needs per-bone sync.

## 10. Networking patterns / pitfalls
**REPO (host-authoritative physics, PUN):** All world physics lives on the MasterClient: objects' photon ownership pinned to master, clients are non-simulating (kinematic-like) and only get velocity+flags at 25 Hz and extrapolate. Players never own grabbed objects; they stream *intent* (hand target point, rotate delta) each tick via serialize-view and send grab/release as RPCs validated with `OwnerOnlyRPC`/`MasterOnlyRPC` helpers (sender check = anti-spoof). Gameplay-critical numbers (valuable value, haul, breakage) are computed only on host and pushed by RPC (`DollarValueSetRPC`, `BreakRPC`), clients are display. Game mode `0` = solo uses the same code path through `if (gameMode==0 || IsMasterClient)` wrappers (single code path for SP/MP; useful for our 1-player case). Pitfalls they work around: velocity clamp 40/30 on host to stop physics explosions; `impulseTimerDeactivateImpacts` (5 s) so spawn/teleport/join doesn't trigger break events; `indestructibleSpawnTimer`, `ImpactDisable`, per-tier cooldowns to stop multi-frame double charging; `clientNonKinematic` for small items so they respond locally; `OverrideKinematic/Deactivate/Teleport` helpers for safe repositioning; objects below y<-50 despawned (`PhysGrabObject.Update`); haul membership polled (0.5 s) instead of trigger events to avoid enter/exit races; `photonView.ViewID != 0` waits before RPC at spawn; held-object sleeping guard (`rb.IsSleeping` -> 0.5 s indestructible when first grabbed so waking up doesn't count as an impact).
**PEAK (owner-authoritative characters, host-authoritative world rolls):** Each client fully simulates its own ragdoll/stamina/afflictions and broadcasts a small `PhotonBinaryStreamSerializer` struct; other players can *push* state onto you only via RPCs that your client applies (`AddStatus(..., fromRPC)`, `DragTowards`, `Fall`, `AddForce`), so help/harm is always "request -> owner applies", which avoids prediction/rollback entirely (e.g. pull-up = helper holds reach, victim's own client applies the 70 force). Items: host spawns and `TransferOwnership` to the character holding them (`Item.cs` Held case), so thrown items are simulated by the thrower; `ItemPhysicsSyncer` sends position, quaternion, half-precision linear/angular velocity at `SerializationRate` and remotes lerp over `1/SerializationRate`; kinematic state is a buffered RPC (`SetKinematicRPC` AllBuffered) so late joiners get it. Host-only systems: spawner rolls + spawn history (for rejoin), campfire/lava timers (synced as start-time + elapsed), revival RPCs. `ReconnectHandler/ReconnectData` snapshots a leaver (statuses, thorns, position, deathTimer, scout report) and restores them on rejoin -> good for friend-slop where people drop. Pitfalls handled: remote `UseStamina` just returns affordability without mutating; statuses clamp via a single `statusSum` so RPC order can't exceed cap; carried players disable collisions to avoid physics fights; carrier-gone fail-safe (`CarrierGone`), un-pass-out fail-safes (3 s tick), `UnPassOutCalled` re-entrancy flags.

## Recommendations (max 12)
1. Quota = fraction of what is actually on the map: `goal = 0.7 * sum(spawned fish value) * curve(level)` (REPO `RoundDirector`, `haulGoalMax`) -> reachable by construction; spec §14.4 quota math in `Core` (M2/M3); keep the 0.7 and a 3-band difficulty (levels 0-9/10-19/20+) as tunables.
